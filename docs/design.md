## Genre

**modern-minimal**

editorial（Hallmark の既定）は採らない。大見出しと潤沢な余白で読ませる構えは、本プロダクトの
絶対原則である「情報削減禁止・鉄道ファン向けの情報密度」と正面から衝突するため。
modern-minimal は白基調・細く見える枠・小さい角丸・計器盤的な密度を許容し、実態に合う。

このジャンルで**許されるもの**: 純白に近い紙、彩度ゼロに近いニュートラル、細く visible な枠線、
2カラムのヘッダ構成、tight-set の大きめ display。
このジャンルで**禁じられるもの**: イタリック見出し、グラデーション文字、グラスモーフィズム、
バウンド/オーバーシュートのイージング、装飾的な飾り罫・ドロップキャップ。

### 色の掟（audit から直接導かれた恒久ルール）

1. **`--color-accent` を紙の上の前景色に使わない。塗り専用。**
   `accent on paper = 2.72:1` で WCAG 1.4.11 の 3:1 に届かない。オレンジの印が要る箇所は
   `--color-accent-deep`（5.76:1）を使う。
2. **accent 塗りの上の文字は `--color-accent-ink`（暗色）。白文字にしない。**
   白文字は 2.79:1 で不合格。暗色なら 6.38:1。accent の L が 70.3% > 50% であるため、
   Hallmark の custom-theme § B.6 が暗色を指定している。
   ※ `styles.scss` の M2 パレットも元々 `accent 500 → contrast: rgba(black,.87)` と宣言している。
3. **フォーカスリングは面ごとに2色持つ。** 単色では navy 面か紙面のどちらかで必ず消える
   （現状 `#001556` はトップバー上で 1.00:1＝完全に不可視）。
   濃色面かどうかは面のクラス（`tw-bg-primary-500` / `tw-bg-structure`）で判定する。
   **要素名 `header` で判定しない** — ダイアログや各ページの白い面にも `<header>` があり、
   明色リングが白地に溶けていた（2026-09-23 修正）。
   **メニュー（`mat-menu`）のパネルにはリングを出さず、項目はキーボードで移ったとき
   （`cdk-keyboard-focused`）だけ出す**（2026-09-24）。右クリック・長押しで開くメニューは
   Material がパネルへプログラムでフォーカスを移し、フォーカスを持てない要素（「休」タグ）から
   開くとそれが `:focus-visible` に当たって、マウス操作なのに赤いリングが出ていた
4. **種別（`tripClass`）は全ページで塗りチップに統一する**（ユーザー指示 2026-08-22）。

    実装は共有コンポーネント `app-trip-class-chip` ただ 1 つ。各ページで span を
    手組みしない。塗り色は `tripClassColor` をそのまま使う。

    - **列車番号をチップに含めない。** チップは種別だけを表し、列車番号は隣に別要素
      として置く。以前は運用表・ダイヤグラム情報パネルで「快速 2002」のように
      1 つのチップに同居していた
    - **セレクトボックスの選択肢はチップにしない**（ユーザー指示 2026-08-22）。
      選択肢と選択中表示は系統付きの正式名（例:「特急（SO→TY）」）を色文字で出す。
      系統付きの正式名は選択肢でのみ用いる規約があり、これを落とすと
      「特急（SO）」と「特急（SO→TY）」が選び分けられなくなる
    - 種別色を**小さな文字色**として紙の上に置かない。ドメイン由来の色
      （`#40c4ff` = 1.99:1 等）は文字にすると読めない

    **対象外**（種別ラベルではないもの。触らない）:

    - 全線時刻表の**時刻セル**の文字色 — 紙の時刻表の作法であり、種別の表示ではない
    - 駅別時刻表の**分**の文字色 — 同上
    - ダイヤグラム・運用行路図の **SVG 線色** — 線そのものが種別を表しており、
      ラベルではない

    **例外: 種別色チップの文字は白のままとする**（ユーザー判断 2026-08-21）。

    - 背景が種別色で塗られたチップでは、文字色を白で統一する。視覚的な一貫性を優先する
    - 結果として一部の種別が AA を満たさない（実測: 特急 `#ff9800` 2.10:1 /
      通勤特急 `#ffb74d` 1.68:1 / 回送 `#9e9e9e` 2.61:1）
    - 代替案を検証したうえでの選択である:
        - _文字色を色ごとに自動選択_（白/黒）すると全種別が 4.5:1 以上になるが、
          チップ内の文字色が混在する
        - *白文字のまま塗りを暗く*すると AA は満たせるが、特急 `#bb5900` と
          通勤特急 `#a86500` が互いに判別不能になり**情報が失われる**（原則1に反する）
    - 緩和として、チップ文字に `.trip-class-chip-label`（`paint-order: stroke fill` +
      `-webkit-text-stroke: 0.08em var(--color-ink-deep)`）で縁取りを与える。
      字面を痩せさせずに輪郭を立て、知覚上の可読性を上げる
    - **縁取りの太さは必ず `em` で持つ。**チップは 10px（sm）と 12px（md）の2サイズあり、
      `px` 固定だと小さい方だけ相対的に太くなる。当初の `2px` は 10px の文字に対して
      0.2em に相当し、「送」「急」「停」など画数の多い漢字の内側の空きが埋まって
      字が潰れていた（2026-08-22 実測・5倍拡大で確認）。0.08em は
      10px→0.8px / 12px→0.96px となり、輪郭を出しつつ字面を保つ上限に近い値である
    - **ただしこれは自動判定を通す対策ではない。** WCAG のコントラスト比は
      文字色と背景色のみで算出されるため、チェッカー上は不合格のまま残る。
      WCAG 2.x は縁取り文字の扱いを定義していない
    - 背景の塗りが無い箇所（`operation/real-time` の種別リンク等）はこの例外の対象外。
      文字は `--color-ink`、種別色は下線が担う

5. **運用番号の群色チップは現状維持。** 12% 透過の背景に暗色文字で AA を満たしており、
   相鉄独自の慣行として意味を持つ。触らない。

    **絞り込みチップの選択色は全ページ共通でオレンジ**（`app-filter-chips` の既定
    `accent`。ユーザー指示 2026-08-22）。ページごとに選択色を変えない。
    オレンジ地の文字と ✓ は `--color-accent-ink`（実測 6.38:1）。白文字にしない。

    **枠線は選択・未選択とも 1px 引き、色だけを変える。**未選択にだけ枠線を
    付けると、選択時に上下 2px ぶん縮んで同じ行のチップの縦幅が不揃いになる
    （実測 34px → 32px。`box-sizing: content-box` のため枠線がそのまま外形に効く）。

    経緯: かつては `operation/real-time` の運用群だけオレンジで、他の 7 箇所
    （運用表・全線時刻表・行路図・ダイヤグラム・列車位置情報・過去運用・時刻表編集）は
    紺だった。いったん全部を紺へ揃えたのち、**オレンジ側に統一**する判断になった。

    **チップ族の区別を選択色でつけない。**`operation/real-time` の会社と運用群は
    **段を分ける**（`app-filter-chips` を 2 つ縦に並べる）。1 行に混在させると
    どちらの軸で絞っているか読み取りにくく、横スクロールでどちらかが見切れる。

6. **鮮度の赤・緑は明度を揃える**（`operation/real-time` の目撃・更新時刻）。

    「赤＝本日中／緑＝昨日」という凡例の意味は変えない。ただし旧値
    （`#f44336` 3.68:1 / `#4caf50` 2.78:1）はどちらも紙の上で AA に届かず、かつ
    赤だけが明るく前に出るため画面全体がエラー表示のように読めていた。
    `--color-recency-today` / `--color-recency-yesterday` として **L=50% に揃えた**
    2色をトークン化する（6.45:1 / 5.49:1）。テンプレートに hex を直書きしない。

    色覚の単一手掛かりにはなっていない。凡例が同じ情報を
    太字（本日）／下線（昨日）でも与えているため、色は補助である。

### 面の掟（カードの境界の作り方）

**カードの境界は影ではなく面の明度差で作る**（ユーザー判断 2026-08-22）。

|                    | 色                         |
| ------------------ | -------------------------- |
| ページ地（`body`） | `--color-paper-2`          |
| カード面           | `#ffffff`（`tw-bg-white`） |

以前はページもカードも `#ffffff` で、**影だけが唯一の境界**だった。
ページ地をひとつ沈めることで、白いカードが影なしで浮き上がる。

-   **カードに影を付けない。罫線も引かない。**面の差だけで分ける
-   検討した代案: 罫線のみ / 面の差＋罫線 / 上辺に紺の罫。実カードを並べて比較し、
    **罫線を足すのは「影をやめる動機（浮きの表現をやめる）」と方向が逆**という理由で
    面の差だけを採った。罫線が増えないので密度の高い時刻表・運用表とも喧嘩しない
-   小カード（`operation/real-time`）の `tw-border-grey-300` も撤去した。
    186 枚並ぶ画面では 1px の枠が視覚的な雑音になる

**操作部品の地は白（`--color-control`）に統一する**（ユーザー指示 2026-09-23）。

-   対象は入力欄（outline の中）・`app-segment-toggle` の未選択側・`app-filter-chips` の
    未選択側・`app-button` の副ボタン
-   入力欄は Material 既定が透明で、ページ地の上では灰（`paper-2`）、カードの上では白と
    置き場所しだいで色が変わっていた。`styles.scss` で outline の中を塗る（角丸は枠線と同じ 4px）
-   セグメント切替・チップ・副ボタンは `--color-paper`（わずかに青い白）だった。
    カード面（白）の上に置くと 1 段だけ沈んで見えたため白に揃えた
-   選択状態の塗り（紺・オレンジ）と、その上の文字色は変えない

**ページ上端の操作部（選択欄・チップ・切り替え）は全幅の白い帯に載せる**（ユーザー指示 2026-10-05）。

-   列車ダイヤグラム・列車位置情報の表示設定と同じ見た目: トップバー直下に端から端までの白地＋下に 1px の罫線（`--color-rule`）。
    中身の左右は本文の余白にそろえる
-   共有部品 `app-control-band`（`shared/control-band`）。main の余白（`tw-p-4 md:tw-p-6 lg:tw-p-8 xl:tw-p-16`）の中に置き、
    上と左右を負のマージンで打ち消して抜く。main の余白を変えるときは部品の値も変える
-   対象: 駅別時刻表・全線時刻表・運用表・運用行路図・リアルタイム運用情報・過去の運用情報。
    中身が無いと出さない操作部（全線・行路図の路線チップ）は、帯ごと出さない
-   比べた代案: 本文の余白の中の白カード。駅別時刻表で実物を並べ、ダイヤグラムと同じ全幅の帯を採った
-   帯の中の選択欄は `subscriptSizing="dynamic"`（入力の誤りを出す欄がないもの）。下に 22px の空きが残るため
-   **帯の中の余白**（「最後に余白を調整して」2026-10-05）: 帯の上下 16px・まとまりの間 16px（`tw-gap-4`）・
    ラベルとチップの間 8px（`tw-mb-2` / `tw-gap-2`）・チップの段の間 8px。チップは Material の既定で上下に 4px の余白を持ち、
    帯の下とラベルの下だけ 4px 広がっていたので、帯の部品の中で `app-filter-chips` に `margin-block: -4px` を当てて打ち消す
    （共有のチップ部品は他のページでも使うので触らない）。チップが横にあふれて常時表示のスクロールバーが出る環境では、
    バーの分だけ帯の下が伸びる（スマホの重ねて出るバーでは伸びない）
-   **ダイヤの選択欄の書式は「2026/3/14改正 平日ダイヤ」にそろえる**（同日。選択肢・選択中の表示とも。
    以前は「2026年03月14日改正」「2026.3.14改正」「2026.3改正」が混在していた）。整形は `formatCalendarSummaryLabel` と同じ
-   **広告（AdSense）は一旦外している**（ユーザー指示 2026-10-05「Adsenseは一旦消して」）。`index.html` の
    `adsbygoogle.js` と各ページの `<ng-adsense>` を外した。戻すときのために `ng2-adsense`・`core.module` の
    `AdsenseModule.forRoot`・`shared/ad-placeholder`・`styles.scss` の `.adsbygoogle` は残してある。
    枠の番号: 全線時刻表 1363071722／駅別時刻表 6036265169／運用行路図 6189336070／運用表 6887340076（どれも検索カードの隣）
-   **絞り込みの見出しは「○○で絞り込み」だけ**（会社・軸が 2 段あるリアルタイムは「絞り込み」）。
    「（表示のみ）」「（経由しない路線は選択不可）」のような括弧の注記を付けない（ユーザー指示 2026-10-05「変な括弧書きは排除して」）

**表や図のカードの上端でダイヤを示すときは、平日青・土休日赤の帯にする**（ユーザー指摘 2026-10-05「わざわざ色付きの帯にしてるのに」）。

-   共有部品 `app-calendar-band`（`shared/calendar-band`）。高さ 48px・白文字 2 行（「2026/3/14改正」／「平日ダイヤ ＋ 何の表か」）、
    色は `styles.scss` の `.weekday` / `.holiday`（土曜か日曜を含むダイヤが赤）。カードの縁まで出し、角丸はカードの `overflow-clip` で効かせる
-   使う所: 駅別時刻表・全線時刻表・運用行路図・列車情報の入力。無地の小見出しで代えない

**「種別 列車番号」は共通部品 `app-trip-label` で出し、列車番号だけを全線時刻表へのリンクにして下線を引く**
（ユーザー指示 2026-10-05「全ページで統一し、リンクであることが判別しやすいように下線を」）。

-   `shared/trip-label`。種別チップはリンクの外、列車番号は `tw-underline`・色は親から継ぐ（`[color:inherit]`）。
    リンク先は全線時刻表のその列車を選んだ状態（`calendar_id` ＋ `trip_direction` ＋ `trip_block_id`）
-   使う所: リアルタイム（列車の位置）・運用表カード・駅別時刻表のマス（本体と ↪ の脚注）・
    列車位置情報の駅の欄・列車ダイヤグラムの情報パネル（押すとパネルを閉じる）。
    運用行路図は SVG なので部品は使わず列車番号の `<text>` に下線を付け、押せるのも列車番号だけにする（画像保存には下線を出さない）
-   **駅別時刻表の分はリンクにしない**。全線時刻表へは列車番号から飛ぶ
-   列車位置情報のカードはカード全体がリンクなので対象外

**角丸は全カード共通で `--radius-card`（8px）**（ユーザー指示 2026-08-22）。

`tailwind.config.js` の `borderRadius` にトークンを通してあるので、
カードは必ず **`tw-rounded-card`** を使う（`tw-rounded` / `tw-rounded-lg` を直に書かない）。
以前は 0px / 4px / 8px が混在していて、`--radius-card` トークンは定義だけされて
**どこからも使われていなかった**。

-   `tw-overflow-hidden` は**内側に独自の地色を持つ帯がある場合だけ**併記する
    （運用表カードの群色ヘッダー・行路図の平日/休日帯）。
    **`tw-sticky` を含むカードに付けてはならない** — 祖先の `overflow: hidden` は
    sticky をスクロールコンテナに閉じ込めて機能を殺す。全線時刻表・駅別時刻表・
    時刻表編集は sticky を持つので付けない（実測: sticky 22要素・死んだもの 0）
-   **sticky を含むカードで帯の角を丸めたいときは `tw-overflow-clip`**（2026-09-23）。
    `overflow: clip` はスクロールコンテナを作らないので、角丸で切り抜きつつ sticky が生きる。
    駅別時刻表の時刻表カード（紺の時の帯 + 時の数字の sticky）が使う
-   **縦にも横にも大きい表は、カードの中で縦横スクロールさせる**（2026-09-24）。横スクロールの
    箱はそれ自体がスクロールコンテナになるので、ページ基準の縦の sticky が効かない。
    中の箱の高さを「画面 − トップバー − 32px」に抑え、見出しの行と列をその中で sticky にする。
    罫線は `border-separate` + 各セルの右・下で引く（過去の運用情報）
-   sticky な帯の下へカードが潜り込むと、カードの上端が帯でまっすぐ切られて角丸が消える。
    帯の真下の左右に、ページ地の色で角丸と同じ半径の「逆向きの角」を描いて補う
    （駅別時刻表の `.sticky-direction-band`）

### 入力の格子（Material 部品の例外）

**UI は Material 部品を包んで使うのが原則だが、列車情報の入力（`timetable/add|copy|update`）の
時刻の格子だけは素の `<button>` と `<input>` で組む**（ユーザー判断 2026-09-30）。

-   理由は 2 つ。打ち込みの速さ（数字 4 桁 → `HH:mm`、Enter・矢印で表計算のように動く）と、
    重さ（`mat-form-field` 1 個 21 要素・ラジオ込みで 1 駅 65 要素。本番の全駅表示では 1 万要素を超えた）
-   例外は時刻の格子のセル（停車種別・着・発）だけ。上の段の列車番号・運用番号・種別・入出庫は Material のまま
-   見た目は掟に合わせる: 時刻のセルの地は白（操作部品の地）、見出しの列と行は `paper-2`、
    経由なし・始発の着・終着の発は `paper-3`、誤りは `red-50` の地に `red-800` の字。
    フォーカスは `--color-focus` の 2px 枠を内側に
-   灰色でも経由なしの欄は打てる（打つと停になる。紙から写すとき停を押す手間を省く）。
    始発の着・終着の発は、その駅の行にフォーカスがある間だけ打てる（上から順に打つと
    最後の駅が毎回終着になり、発が打てなくなるため）。灰色の欄は値を空に見せる
-   罫線は `border-separate` ＋各セルの右・下。列車の境目は `rule-strong`
-   ほかの画面で同じ理由の格子が欲しくなったら、先にここへ足してから組む（例外を黙って増やさない）

### 会社・路線の並び

    -   2023-03 相鉄・東急直通線: 東急 → 横高 → 東京メトロ → 東武 → 西武 → 埼玉高速 → 都営

    畳んだ見出しの要約は、全部選んだときも何も選ばないときも「全路線」

### 運用群

**運用群 = 運用番号の最初の 1 桁 + 記号（存在する場合）**（ユーザー確認 2026-08-22）。
`11 → 1群` / `50 → 5群` / `91G → 9G群` / `01K → 0K群` / `51K → 5K群`。
**運用番号 100 は休車であり運用群ではない**ので「休」として別扱いする
（規則をそのまま当てると「1群」に混入する）。
**タグ・チップでは「休」と出し、行路図へのリンクを張らない**（行路図が無い）。
`app-operation-number-tag` は部品の中でこれを行う（2026-09-24。real-time の編成順カードは
`app-new-operation-number-link` 側で同じ扱い）。

-   **並び順は 記号なし → G → K → 休。** そのまとまりの中で数字の昇順。
    数字より記号を優先して束ねるのは、その単位が意味を持つため
-   実装は `shared/operation-group.util.ts` の
    `deriveGroupName` / `deriveGroupNames` / `compareGroupNames`。チップの選択肢は `operationGroupOptions`
    （リアルタイム運用情報と運用表で共有。2026-09-25 に real-time の util から移した）
-   **チップの出所は API の群定義ではなく実在する運用番号。**
    API `/v3/operations/groups` は本来 15 群あるべきところ 5 群しか返しておらず、
    実データ 93 運用番号のうち 60 件が絞り込めなかった（2026-08-22 実測）。
    server 側の修正は別途。直すときはこの規則に合わせること

### 運用順・編成順の見出し

**幅が変わっても「どちらが何順か」の示し方を切らさない**（ユーザー指示 2026-08-22）。

-   `md` 未満: `mat-tab-group` で切り替え（帯は画面端まで抜く。余白の掟 4）
-   `md` 以上: 横並びにしたうえで、**各列の頭にタブと同じ見た目の見出し行**を置く

見出し行はモバイルのタブ帯と同じ値に揃える。ここがズレると、幅を変えたときに
別物を見ている感覚になる。

| 項目     | 値                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 帯の高さ | 48px（`tw-box-border` 必須。preflight 無効で既定が content-box のため、付けないと下罫 1px ぶん 49px になる） |
| ラベル   | 14px / weight 500 / tracking 1.25px / `--color-structure`                                                    |
| 下線     | 2px `--color-structure`（ラベル幅ぶん）                                                                      |
| 帯の下罫 | 1px `--color-rule`（列幅いっぱい）                                                                           |

**タブ部品は使わない。** 横並びでは切り替えが起きないので、`mat-tab` を置くと
操作できない偽タブになる。実体は見出しなので `<h2>` を使い、見た目だけタブの
言語に寄せる。両方が常に見えている状態なので、**両方とも「選択中」の見た目**にする。

### リアルタイム運用情報のカード

2 行構成にする。

**上段の左端は「そのリストの並び順の主キー」**（ユーザー指示 2026-08-22）。
2 つのカードで主従が逆になる。左端を目で追えば並び順どおりに読める。
**下段は主キーの列に合わせず、カードの左端から全幅を使う**（同指示）。

```
運用順カード（運用番号順）          編成順カード（編成番号順）
┌──────────────────────┐   ┌──────────────────────┐
│ [運用番号] 編成番号 形式・会社 目撃/更新 │ │ 編成番号  [運用番号]  目撃/更新 │
│                                │   │ 形式・会社                     │
│ 履歴                           │   │ 履歴                           │
│ [種別] 列番  発駅 → 着駅       │   │ [種別] 列番  発駅 → 着駅       │
└──────────────────────┘   └──────────────────────┘
   ↑ 下段はここ（カード左端）から始まる
   ※ 位置は横並び。幅が足りなければ「発駅 → 着駅」が次の行へ折り返す
```

**編成番号を常時太字にしない。** 凡例が「太字＝本日中に目撃された情報」と
定義しているので、常時太字は凡例と衝突する。鮮度は運用順カードでは編成番号の
`[class.tw-font-bold]="dayCount === 0"`、編成順カードでは運用番号チップの
`textStyle` が表す。

以前は履歴が編成番号と同じセルに積まれ、目撃/更新が 2 行ぶん縦に伸びていた
（ユーザー指摘 2026-08-22）。

**編成順カードの左列は 72px 固定**（`tw-grid-cols-[72px_1fr_auto]`）。
`auto` にすると列幅が形式・会社名に引きずられ（`8000・相鉄` 63px /
`10000・相鉄` 69px / `E233-7000・JR東日本` 121px）、右隣の運用番号チップの
左端がカードごとにガタつく。**長い形式名は折り返して 2 行にする — 省略はしない**
（情報削減禁止）。編成番号には `tw-tabular-nums` を当てて桁の揺れも殺す。

**編成番号と形式・会社は、編成順カードでだけ縦に分ける**（ユーザー判断 2026-09-23）。

-   **編成順カード**: 編成番号（主）／ 形式・会社（修飾）の縦 2 段。編成番号が並び順の
    主キーで左列を 72px に固定しているため、横に並べると列から溢れる
-   **運用順カード・ダッシュボードの目撃情報**: `10706 10000・相鉄` と横 1 行に並べ、
    入らなければ形式・会社が次の行へ折り返す。主キーは運用番号で、編成番号の列幅に
    縛りが無い

2026-08-22 時点では「主データと修飾は縦に分ける。横に並べると主役が読み取れない」
として全カードで縦 2 段にしていた。主従は文字の太さ・大きさ・色（`--color-muted`）で
十分に表せており、縦に積むとカードの高さだけが増えていた。

**上段の 3 要素（運用番号チップ・編成・目撃/更新）は行の縦中央でそろえる**
（`tw-self-center` / `tw-items-center`。ユーザー指摘 2026-09-23）。高さがそれぞれ
チップ 28px・編成 1 行 20px（編成順は 2 段 35px）・目撃/更新 2 段で揃わないため、
上揃えだと編成番号がチップより 4〜5px 上に浮く。3 カード種とも中心のずれ 0px を実測で確認。

**見出し列（`履歴` / `現在位置` / `目撃時`）は 2.5rem 固定**（ユーザー判断 2026-09-23）。
一番長い `現在位置`（10px × 4 文字 = 40px）に合わせる。以前は `auto` で、カードごとに
「履歴」だけなら 20px・「現在位置」があれば 40px と幅が変わり、本文の左端が
カードやページ（ダッシュボードの `目撃時` は 30px）ごとにずれていた。

**位置（種別チップ + 列車番号 と 発駅 → 着駅）は横に並べ、入らなければ折り返す**
（ユーザー判断 2026-09-23）。2026-08-22 時点では上の規則に含めて常に縦 2 段に
していたが、これは主従の関係ではなく「どの列車が・どこからどこへ」を 1 文で読む
並びなので、幅があるときに縦に積む理由が無い。

-   実装は共有部品 `app-trip-position`（`src/app/shared/trip-position/`）ただ 1 つ。
    `operation/real-time` の 2 カードとダッシュボードの目撃情報が使う
-   `flex-wrap` の横並びで組み、**固定の判定幅は持たない**。必要な幅は中身で
    150〜290px とばらつく（2026-09-23 実測）ため、閾値を決めるとどこかで溢れる
-   運行中の列車が無いとき（出庫前・入庫済・不明）は種別も列番も出ないので、
    発着だけの 1 段になる。分岐を書き足す必要はない

## Spacing

4pt スケール。値は `src/tokens.css`。ページは必ず名前付きトークンを使う（生値を書かない）。

```
3xs 4px  2xs 8px  xs 12px  sm 16px  md 24px  lg 32px  xl 48px  2xl 72px
```

### 余白の掟

1. **ページ外周 gutter は段階的に広げる。**全ページの `<main>` が同一の1本の
   クラス列を持つ（`grep '<main' src/app/pages` で常に一致すること）:

    ```
    tw-flex tw-flex-col tw-gap-4 tw-p-4 md:tw-p-6 lg:tw-p-8 xl:tw-p-16
    ```

    | 幅          | gutter |
    | ----------- | ------ |
    | `< 768`     | 16     |
    | `768–1023`  | 24     |
    | `1024–1279` | 32     |
    | `≥ 1280`    | 64     |

    旧実装は `md` 以上が一律 64 で、**768px では左右で画面の 17%（128px）を
    余白に使っていた**。情報密度が本プロダクトの絶対原則なので、狭い側ほど
    gutter を締める。また 767→768px の 1px で 16→64 と跳ぶ段差も解消した。

    **スマホの横 gutter は 0 にしない**（ユーザー判断 2026-08-22）。
    かつては `max-sm:tw-px-0` で 640px 未満の横 gutter を殺していたが
    （2026-07-20 の規約）、カードの枠が画面の縁に密着して窮屈に見えるため
    撤回した。**16px は Material の画面マージン既定と一致**し、`sm` 帯とも
    同じ値なので、gutter の階段は 16 → 24 → 32 → 64 と単調に並ぶ。

2. **canvas 系ページ（`train-diagram` / `train-location`）は外周 gutter を持たない。**
   図そのものが本文であり、幅を削ると情報が減るため。**これは意図的な例外**で
   あって実装漏れではない。ただし

    - `<main>` ランドマークは他ページと同じく必ず置く
    - 図の上下に置く chrome（操作行・凡例・注記）は**横 12px の inset で揃える**。
      0 にすると右端の文字が画面の縁に密着して切れて見える

3. **何も描画しないコンポーネントを flex の子に残さない。**`@if` が false で
   コメントノードだけになったホストも flex item として `gap` を消費する。
   `styles.scss` の `main > :empty { display: none }` で一括して殺している。
   全線時刻表の未選択時、これで本文が 32px（gap 16 × 2）下がっていた。

4. **帯として読ませる部品だけ gutter を突き抜けさせる。**タブ帯のように
   「画面幅いっぱいのコントロール」として読ませたい要素は、負のマージンで
   外周 gutter を打ち消し、**中身の側で同じ値を戻す**（ユーザー指示 2026-08-22）。
   これをしないと、帯まで内側に寄って中途半端に見える。

    ```html
    <!-- 例: operation/real-time のモバイルタブ -->
    <div class="tw-mx-[-16px] md:tw-hidden">
        <mat-tab-group>
            <mat-tab label="運用順">
                <div class="tw-px-4 tw-pt-3">…</div>
            </mat-tab>
        </mat-tab-group>
    </div>
    ```

    打ち消す値を 16px 固定で書いてよいのは、この要素が `md` 未満でしか
    出ないため（その帯では gutter が常に 16px）。**md 以上でも出る要素に
    同じ手を使うときは、gutter の段階に合わせて負のマージンも段階化する。**
    カード・チップ・凡例といった通常の中身は突き抜けさせない。

## Motion

-   イージング: `--ease-out: cubic-bezier(0.16, 1, 0.3, 1)` / `--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1)`
-   所要: `--dur-short: 160ms` / `--dur-med: 240ms`
-   **Reveal パターン: なし。** スクロール連動のフェードインは使わない。データは即座に出す
-   `transform` と `opacity` のみアニメーションする。レイアウトプロパティは動かさない
-   `prefers-reduced-motion: reduce` で空間移動は 150ms 以下の不透明度クロスフェードに落とす
-   **フォーカスリングはアニメーションさせない。** 即座に出す
