# zoneless 化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** client から zone.js を外し、Angular 22 の既定の zoneless 変更検知で動かす。

**Architecture:** 先にテスト環境を zoneless にして、zone 頼みの spec を洗い出して直す（アプリはまだ zone のまま）。次にアプリから `provideZoneChangeDetection()`・zone.js・`NgZone.run` を外す。最後に本番ビルドを実データで確かめ（コントローラ）、ADR を書く。

**Tech Stack:** Angular 22.2・jest 30＋jest-preset-angular 16.2.0・@testing-library/angular・NgRx SignalStore

**Spec:** `docs/superpowers/specs/2026-11-04-zoneless-design.md`

## Global Constraints

- `provideZonelessChangeDetection()` は書かない。v21+ の既定なので `provideZoneChangeDetection()` を外すだけ。
- 部品の書き換え（signal 化・OnPush 化）は、止まる所が見つかったときだけ、その部品に限る。
- SSR の `renderQueue`（server.ts）は触らない。デプロイのワークフローは直さない。
- コミットは Conventional Commits＋絵文字（例 `refactor: :recycle: …`）・GPG 署名（サンドボックス外）・末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` と `Claude-Session: https://claude.ai/code/session_01FZB1eB3dTj4GQVxda71thf`。
- jest は `npx jest`（単体は `npx jest --testPathPatterns=<path>`）。lint は `npm run lint`（サンドボックス外）。prettier はファイル単位で、触った ts/html/json だけ。
- パイプで連結しない・`git stash` を使わない。

## Review Focus

1. 裏に回したタブから戻ったとき、リアルタイムの時刻と在線がすぐ今に追いつく（interval は rxjs のまま。Task 2 の spec で tick→描き直しを固定、実地は Task 3）。
2. SSR がデータの入る前の HTML を返さない（Task 3 の HTML 比べ。差は PendingTasks で直す）。
3. Material のダイアログ・メニュー・スナックバーが開閉し、閉じた後に親の表示が変わる（Task 3 の実地）。
4. 時刻表入力（reactive forms・`markForCheck`）で行の追加・削除・入力が画面に出る（Task 3 の実地）。
5. 設定保存の間引き（`with-settings-storage` の setTimeout）が zoneless でも書き込む（既存 spec が Task 1 で zoneless 下で通ること＋Task 3 で IndexedDB を見る）。

### Task 2: アプリから zone.js を外す

**Files:**
- Modify: `src/main.ts`・`src/main.server.ts`（`provideZoneChangeDetection()` と import を消す）
- Modify: `angular.json`（build の `"polyfills": ["zone.js"]` の行を消す。test ターゲットに有ればそれも）
- Delete: `src/polyfills.ts`／Modify: `tsconfig.app.json`（`files` から `src/polyfills.ts` を外す）
- Modify: `package.json`・`package-lock.json`（`npm uninstall zone.js`）
- Modify: `src/app/core/utils/run-interval-in-browser.ts`（`NgZone` を外し、`afterNextRender` の中で直に `interval(...).pipe(takeUntilDestroyed(destroyRef)).subscribe(...)`。JSDoc の zone の説明を「tick が signal を書けば zoneless の予約で描き直される」に直す）
- Test: `src/app/core/utils/run-interval-in-browser.spec.ts`

**Interfaces:**
- Consumes: Task 1 の zoneless TestBed。
- Produces: `runIntervalInBrowser(periodMs: number, tick: () => void | Promise<void>): void`（署名は変えない）。

- [ ] **Step 1: 失敗するテストを書く** — `run-interval-in-browser.spec.ts` に `it('tick が signal を書くと、変更検知を手で呼ばなくても表示が変わる')`。`ChangeDetectionStrategy.OnPush` のホスト部品が constructor で `runIntervalInBrowser(1000, () => this.count.update((n) => n + 1))` を呼び、テンプレートに `{{ count() }}` を出す。`jest.useFakeTimers()`、描画後に `jest.advanceTimersByTime(3000)`、`await fixture.whenStable()` の後、`fixture.detectChanges()` を呼ばずに `expect(fixture.nativeElement.textContent).toContain('3')`。
- [ ] **Step 2:** 走らせる。今の実装（NgZone.run）でも通るなら、それでよい（テストは zoneless で止まらないことを固定するためのもの）。落ちたら原因を report に書く。
- [ ] **Step 3:** 上の Files の変更を入れる。
- [ ] **Step 4:** `npx jest` 全体・`npx tsc -p tsconfig.app.json --noEmit`・`npm run lint`・`npm run build:prod` が通る。build の出力に `polyfills-*.js` が無いこと、`grep -r "zone.js" src angular.json package.json tsconfig*.json` が 0 件であることを report に書く。
- [ ] **Step 5:** Commit 2 本 — `refactor: :recycle: zone.js を外して zoneless で動かす`（main・angular.json・polyfills・tsconfig・run-interval と spec）と `build: :heavy_minus_sign: zone.js を依存から外す`（package.json・package-lock.json）。
