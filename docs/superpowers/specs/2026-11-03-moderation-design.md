# M18 投稿の見回り（client）

- **日時**: 2026-11-03
- **ブランチ**: feature/moderation（api・client・backend）
- **全体の設計**: api の `docs/superpowers/specs/2026-11-03-moderation-design.md`（なぜ・役割・データ・口はそちら）。この文書は画面だけ。
- **下書きの画像**: `.superpowers/brainstorm/709550-1793638275/entry.png`・`user-page.png`（git 管理外）

## なぜ

荒らしの片付けを EDITOR が 1 件ずつ押していた（30 日で 491 件・1 人）。一人の投稿をまとめて無効にし、MANAGER が BAN でき、同じ人の別アカウントを手がかりで見つけられる画面を作る。

## 決めたこと（ユーザー判断）

- **入口は両方**（下書きの C）。
  - A: 過去の運用表で目撃のセルを押すと出る今のメニュー（無効化・復元。`operation-past-time-table`）に「この投稿者を見る」を足す。EDITOR 以上にだけ出す。
  - B: 新しい「見回り」ページ。新しい順の目撃を投稿者つきで一覧にし、「登録して間もない」「短い時間に何件も」の印を付ける。EDITOR 以上にだけメニューに出す。
- **投稿者のページ**（下書き `user-page.png`・ユーザー「いいだろ」）。上から 3 段。
  1. アカウントの情報（EDITOR 以上）: ユーザー名・表示名・役割・登録日時・投稿数・無効数・最初と最後の投稿。
  2. 投稿の一覧（EDITOR 以上）: チェックで選び「選んだ N 件を無効にする」。「まだ有効なものを全部選ぶ」。無効のものは灰色で、誰が無効にしたかを出す。
  3. MANAGER だけ: BAN（viewer に格下げ・理由を書いて確定）と解除。手がかりの表（IP・端末・回数・同じ手がかりの他のアカウント。BAN 済みは赤い印で、押すとその人のページへ）。
- 投稿者の名前は EDITOR 以上にだけ見せる。一般の利用者には今までどおり出さない。
- 役割の名前 `reader` は `viewer` に改める（api の spec）。client の役割の型にも `viewer` を足し、`viewer` は投稿フォームを出さず「投稿できません」と案内する（文言は builder）。

- 投稿者の無い目撃（ゲストの投稿。2026-11-06 21:00 までの分）は、見回りの一覧で「ゲスト」と出し、投稿者のページへは行けない。過去の運用表のメニューにも「この投稿者を見る」を出さない。
- 手がかりの表には、その IP を使ったアカウントの数を出し、多いもの（目安 10 以上）は弱めて出す（携帯回線などの共有 IP の誤認を防ぐ。api の spec 5 章）。
- 自分と MANAGER のページには BAN のボタンを出さない。

## 守ること

- `docs/design.md` の掟（操作帯・Material 部品・Tailwind の `tw-`・余白 4px）。過去の運用表のメニューは今の見た目のまま 1 行足すだけ。
- まとめての無効化・BAN は確認のダイアログを出す（件数・対象の名前を書く）。取り消せる操作でも、押し間違いで 100 件消えると戻すのが大変。
- ルートは EDITOR 以上・MANAGER のガードで守る（今の `timetable-edit.guard` と同じ形）。SSR では描かない（ログインが要る・CDN に置かない）。`app.routes.server.ts` で CSR に。
- 新しいページの名前とディレクトリは対称に（例 `moderation/` と `moderation-user/`。名前は builder）。

## builder に任せること

- ページの名前・パス・部品の分け方、印の出し方、空の状態、読み込み中の骨組み。
- 実データでの見た目の確かめ（手元の api は本番 DB を読む。BAN・無効化は本番に書くので、確かめは保存テスト用のアカウントで、元に戻せる範囲だけ）。
