# M13 目撃募集とマイページ（client の分）

2026-11-03。ロードマップ M13。api の分（`/v3/users/me` の 2 本と「裏付け」の判定）は api の spec `docs/superpowers/specs/2026-11-03-my-page-design.md` にある。ユーザーは設計を私に任せた（「任せる」）。以下の決定はすべて私の判断で、ユーザーの承認はこの spec のレビューで受ける。

## なぜ

11/6 21:00 に目撃の投稿を登録者だけにする（M1 登録制②）。登録した人が、また開いて投稿したくなる理由を作る。

- 目撃募集: 「いま走っているのに、今日まだ誰も見ていない運用」を見せて、見かけたら出してもらう。
- マイページ: 自分の投稿の数と、他の人の目撃との合い方を見せる。

本番の実測（2026-10-30 平日・11-01 土休日）: 平日は 104 運用のうち朝 9 時までに 83 運用に目撃が付き、昼過ぎまで 90 前後で止まる。土休日は昼でも 2 割ほど目撃が無い。一日の終わりにはほぼ埋まる。だから「目撃の無い運用の全部」ではなく「いま走っている」ものに絞る。

## 1. 目撃募集（リアルタイム運用情報）

### 何を出すか

今日のダイヤの運用（休車 100 を除く）のうち、次の両方を満たすもの。

- **いま走っている**: 在線（`currentPositions[運用番号]`）で、`current`（いまの列車）がある、または `prev` と `next` の両方がある（折り返しの間）。出庫前（`prev` が無い）と入庫後（`next` が無い）は出さない。
- **今日まだ目撃が無い**: 今日の履歴（`operationSightingHistories[運用番号]`。4 時の境目・直接の有効な目撃だけ）が取得済みで空。

絞り込み（会社・運用群）が効いているときは、運用順の一覧と同じ `filterRealTimeOperations` を通した後で数える。並びは運用順の一覧と同じ。

新しい API は要らない。real-time がすでに取っている在線と今日の履歴から導く。履歴が届く前・在線が届く前は出さない（数え違いで「募集」が光らないように）。在線は 1 秒ごとに更新されるので、それに合わせて増減する。

### どう見せるか

操作帯の要約の行の下、凡例の上に、白い帯を 1 本置く（貼り付かない）。中身は 1 行:

> 目撃募集　いま走っていて、今日まだ目撃の無い運用　[12K] [58S] [61K] …

- 運用番号は運用群の色のチップ（運用順のカードと同じ部品）。押すと投稿ダイアログを、その運用番号を入れた状態で開く（行の投稿ボタンと同じ `OperationPostDialogService.open({ operationNumber })`）。
- 対象が 0 件のときは帯ごと出さない。
- チップが 1 行に収まらなければ折り返す（最大でも 1 ダイヤの運用数・約 100 件。実測では昼の平日で十数件）。
- ゲスト（11/6 以降は投稿できない）と viewer（BAN）には、チップを押すとログインのページ（`return_to` 付き）へ送る。ゲストに帯を隠さないのは、登録の誘いになるから。viewer は帯ごと出さない。

これはロック済みの real-time に新しい面を足す変更なので、**先に `docs/design.md` の「ロック済みページ」と「操作カード」の節に掟を書き足してから**実装する。掟の文案:

> リアルタイム運用情報の「目撃募集」の帯（2026-11 M13）: 操作帯の下・凡例の上に貼り付かない白帯を 1 本。いま走っていて今日まだ目撃の無い運用を、運用群の色のチップで並べ、押すとその運用番号で投稿ダイアログを開く。0 件なら帯ごと出さない。凡例と同じ左右の余白・上下 8px。

### 作らないもの

- 目撃が無い運用のカードそのものに印を付けること（カードの 2 行構造と上段の 36px を崩す）。
- 通知・プッシュ（M15）。
- 出庫前の運用の予告。

## 2. マイページ

### 入口

- ルート `/my-page`（`pages/my-page`）。トップレベルに置く（ページ名とディレクトリの対称の掟）。
- サイドナビ: ログイン中（viewer を除く）だけ「アカウント」の見出しと「マイページ」を出す。置き場は「管理」の上。
- ヘッダー: 「ようこそ ○○ さん」の名前を `/my-page` へのリンクにする（ログイン中だけ）。
- ガード: `pages/my-page/guards/my-page.guard.ts`。moderationGuard と同じ形（token と profile を先に取る → 未ログインは `/login?return_to=…` → viewer は通知して `/`）。パスの無い親に `canActivate` と `runGuardsAndResolvers: 'always'`。
- SSR: 個人のページなので、`app.routes.server.ts` では投稿管理のページと同じ描き方（サーバーで描かない）にする。sitemap には足さない。
- ページ名の大見出しは置かない（ツールバーと二重になる）。

### 中身

上から 2 枚のカード。

1. **要約**: 投稿数・裏付けあり・別の運用の目撃あり・他の目撃なし・無効にされた数・最初と最後の投稿日時。下に注記「ログインして出した目撃だけを数えます（記録は 2026年10月24日から）。裏付けは、同じ日に他の人が同じ編成を同じ運用で見たかどうかです。」
2. **投稿の一覧**: 新しい順。1 行に 目撃の日時・運用番号（運用行路図へのリンク）・編成番号・裏付けの印。下に「もっと見る」（キーセット、`before`）。

裏付けの言葉（api の `corroboration`）:

| 値 | 画面の言葉 | 色 |
|---|---|---|
| corroborated | 裏付けあり | 緑系（`--color-recency-today` は使わない。新しい意味の色は design.md の色の掟に足す） |
| conflicting | 別の運用の目撃あり | 色を付けない（間違いと断じない。運用の変更や同日引き継ぎで正しい投稿でもこうなる） |
| uncorroborated | 他の目撃なし | 灰 |
| invalidated | 無効 | 灰・取り消し線なし |

- 手本は `pages/moderation/moderation-user`（要約＋一覧＋もっと見る、ストアの持ち方、世代番号、重複排除）。部品・日時の書式（`format-tokyo-date-time.util.ts`）はそこから共通へ出すか、そのまま import する。
- 数字の順位・正答率・他の人との比較は出さない（数を競わせると雑な投稿が増える）。
- 0 件のときは「まだ投稿がありません」と、リアルタイム運用情報へのリンク。

### libs

- `libs/user` に `findMySummary()`（`GET /v3/users/me`）、`libs/operation-sighting` に `findManyMine(params)`（`GET /v3/users/me/operation-sightings`）。DTO は管理者向けの `OperationSightingSummaryDto` に `corroboration` を足したもの。

## 確かめ方

- 目撃募集の導出（走っている判定・履歴の空・絞り込み・取得前は出さない）を util の単体テストで。
- 帯の 0 件で出ない・チップでダイアログが運用番号つきで開く・ゲストはログインへ、を component の spec で。
- マイページの guard（ゲスト → login、viewer → `/`、reporter は通る）、ストア、一覧の「もっと見る」の spec。
- 実データで目視: 手元（本番 DB を読む）で real-time を 320/375/768/1440 で開き、帯の折り返しと横はみ出しが無いこと、凡例との縦の間隔。マイページを reporter と editor で開く。
