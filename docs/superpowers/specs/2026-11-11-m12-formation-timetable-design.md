# M12 編成別時刻表 設計

- 日時: 2026-11-11
- ブランチ: feature/m12-formation-timetable
- ロードマップ: M12「編成の逆引き」（client の docs/roadmap.md）
- モック: `.context/m12-mock-v2.png`（git の管理外。2026-11-11 の 8713・55 運用の本番データで描いた）

## 目的

撮りに行く人が、狙った編成が今日（と明日）どの列車に入り、いつどの駅を通るかを前もって調べられるようにする。現地に住んでいない人が、家で計画を立てるときにも使う。過去の日付を選べば、その日にその編成がどの列車に入っていたかも見られる。

いまのサイトでこれを調べるには、リアルタイム運用情報でその編成の運用番号を見て、運用行路図を開き、列車ごとに全線時刻表で時刻を引く必要がある。このページは、その手間を 1 画面にまとめる。

## 名前と置き場所

- 画面の名前は「編成別時刻表」。駅を決めてその駅の時刻を並べる「駅別時刻表」と、軸だけが違う作りにそろえる。
- URL は `/timetable/formation?formation_number=8713&date=2026-11-11`。`date` を省いたら今日にする。ファイルは `pages/timetable/timetable-formation/` に置き、駅別時刻表（`/timetable/station`・`pages/timetable/timetable-station/`）と並べる。
- 編成番号は日付で区切れば 1 本に決まる。同じ番号の行は本番に 5 組あるが、`start_date`・`end_date` の期間はどれも重ならない（2026-11-11 確認）。その日に有効な編成を選ぶ。
- ページ名の大見出しは置かない（ツールバーが出している）。

## 決めたこと

### 上の段

- 編成番号、形式、両数、会社。
- 今日の目撃を時刻順に並べる（例「9:06 55 で目撃 → 15:40 59 で目撃」）。
- いまの運用と、その根拠を出す。根拠は、今日の目撃、ダイヤの乗り移り、「?」付きの順送り、「?」付きの同日引き継ぎ、不明のどれか。決まりはリアルタイム運用情報と同じにする。
- いま走っている列車と、どの駅の間にいるか。ダイヤどおりに走った場合の位置で、列車位置情報と同じ出し方。
- 明日の見込みの運用（例「56?（順送り）」）。
- 「駅で絞る」の駅を選ぶ欄。
- 日付を選ぶ欄と、前の日・次の日に移るボタン。

### 本体（列車ごと・最初に開く画面）

- その日の列車を、最初の出庫から最後の入庫まで時刻順に並べる。1 行に、種別、列車番号、始発駅と時刻、終着駅と時刻を出す。回送も出す。
- 過ぎた列車は薄く、走っている列車は色を付けて出す。
- 行を押すと、その列車の各駅の時刻が開く。通過する駅は「通過」と出す。時刻表のデータは、通過駅の時刻を持っていない（`times` の行はあるが、時刻は null）。
- 次の 3 つの所に、区切りの帯を入れる。
  - 入庫・出庫（○・△）。星川の一時入庫のように、日中の入出庫も出す。
  - ダイヤで決まっている乗り移り（□）。`itinerary-links` で分かる。帯の先は、移った先の運用の列車を続けて出し、上の段の運用も「16K → 15K」と並べる。目撃が無くても確かなことなので、「?」は付けない。
  - 目撃で分かった車両交換。後述。

### 駅で絞る

- 同じページの中の切り替えにする。駅を 1 つ選ぶと、その編成がその日にその駅を通る列車だけが並ぶ。
- 1 行に、上り・下り、種別、列車番号、着時刻と発時刻、行先を出す。上に、通る回数（済み・残り）を出す。
- 通過する駅を選んだときは、その列車を「通過」として出す。時刻は出さない。

### 日付

選べるのは、過去の日付、今日、明日の 3 種類。日付によって出し方を変える。

- **過去の日付**: その日の目撃と同日引き継ぎから、その編成が入っていた運用の列車を並べる。決まりは過去の運用情報と同じにし、同じ日・同じ編成なら 2 つのページで同じ運用が出るようにする。「いまの位置」は出さず、列車はどれも済みとして出す。その日に目撃が無ければ、「この日の目撃はありません」と出す。過去の日に順送りの推測はしない。過去の運用情報もしていないため。
- **今日**: これまでの節のとおり。
- **明日（見込み）**: 明日の運用が順送りで決まるときだけ選べる。明日のダイヤでその運用の列車を同じ形で並べ、見込みであることを上の段に出す。順送りの無い群（8 群・3G・4G・K の群・50・74〜79・休車の 100）や、運用が不明のときは選べない。選べない理由を日付の欄の近くに出す。
- 明後日より先は選べない。
- 明日の見込みは、最後に目撃された運用から出す。車両交換で 59 に移ったなら、明日は 51? になる。

### 途中で運用が変わったとき（車両交換）

ダイヤで決まっている乗り移りとは別に、故障や遅れで編成が別の運用に入れ替わることがある。前もっては分からないので、目撃で扱う（ユーザー承認 2026-11-11）。

1. 列車の並びを、その編成の目撃で区切る。最後の目撃より前は、その時点で目撃されていた運用の列車を出す。後は、最後に目撃された運用の列車を出す。切り替わった所に「15:40 の目撃で 59 に変わった」の帯を入れる。
2. 目撃と目撃の間の列車は、どちらの運用を走ったか確かではない。過ぎた列車として薄く出し、「推定」と小さく添える。
3. 別の編成がこの編成の運用で目撃され、この編成は新しく目撃されていないときは、追い出されて行き先が分からない状態になる。そこから先は「不明」とし、「最後に分かっているのは 55（15:20 に 8711 が 55 で目撃されるまで）」と出す。投稿への導線を置く。今の api とリアルタイムのカードも、この場合は不明にしている（api #203）。
4. ページを開いたまま新しい目撃が入ったら、リアルタイム運用情報と同じく socket の合図で取り直す。

### このページへのリンク

- リアルタイム運用情報の編成番号（運用順・編成順のどちらのカードからも）。
- 車両のページ（`/library/vehicle`）の各編成。
- このページの上の欄で編成番号を打つ。
- トップのクイックタイルと、ヘッダーの「?」の説明（`page-help.ts`）、使い方のページの「やりたいこと別の使い方」にも足す。

### 見た目の決まり

- 運用番号は群の色のチップ（`operation-number-color.pipe`）で出す。
- 種別の色はデータの `tripClass.tripClassColor` から取る。画面に色を書かない。
- モックの色は仮のもの。

## 使うもの

api に新しいエンドポイントは要らない見込み。どれも今あるエンドポイントで取れる。

- 編成の今日の運用: `GET /v3/operation-sightings/time-cross-section/formation-number/:formationNumber?searchTime=`。目撃・同日引き継ぎ・順送りを、リアルタイム運用情報と同じ決まりで解く。
- 明日の見込み: 同じエンドポイントに、明日の日時を `searchTime` で渡す。最後の目撃からの日数で順送りを進める作りなので出せるはずだが、未来の日時で試してはいない。計画の最初の手順で確かめる。
- 編成の今日の目撃の並び: `GET /v3/operation-sightings/from/:start/to/:end` を編成で絞る。
- 運用の列車と各駅の時刻: `GET /v3/operations/:id/trips`（運用行路図が使っている）。
- 乗り移り: `GET /v3/operations/itinerary-links?calendarId=`。
- いまの位置: `GET /v3/operations/:id/current-position`。

## 実装の決まり（設計者の判断）

読み手の確認で出た問いに、設計者が次のように決めた。ユーザーの確認は受けていない。

- **今日の目撃の並び**: `from/:start/to/:end` で、その日の 4 時から今までの目撃を全部取り、client で編成ごとに絞る。1 日の投稿は 95〜145 件（2026-11）なので量は問題にならない。api には足さない。
- **列車の並びの組み立て**: 次の順に決める。
  1. 最初の運用は、その日の最初の目撃の運用にする。目撃が無ければ、time-cross-section が返す運用にする。
  2. ダイヤの乗り移り（`itinerary-links`）は、日の終わりまで何段でもたどる。最初の目撃より前の時間も、乗り移りを前にさかのぼって決める（15:00 に 15K で目撃され、ダイヤで 16K から 15K へ移るなら、朝は 16K）。
  3. 目撃のほうがダイヤより強い。ある時刻に別の運用で目撃されたら、その時刻を含む列車から目撃の運用に切り替え、そこからまた乗り移りをたどる。
  4. 同じ運用に戻ってきたときも、時刻順にそのまま並べる。
- **「不明」の判定**: client で組み立てる。この編成の最後の目撃より後に、同じ運用で別の編成の目撃があれば、そこから先を不明にする。「最後に分かっているのは 55（15:20 に 8711 が 55 で目撃されるまで）」の 15:20 と 8711 は、その目撃から取る。time-cross-section の `expectedSighting` が null になることと突き合わせて確かめる。
- **明日の見込み**: time-cross-section に明日の 12:00 を `searchTime` で渡す。返る `expectedSighting.operation` は明日のダイヤの運用になる作り（`#createDirectSource` が `searchTime` の日付でダイヤを引く）なので、その運用 id で `/operations/:id/trips` を呼ぶ。未来の日時で正しく返るかは、計画の最初の手順で本番に問い合わせて確かめる。正しくなければ、api を直す作業を計画に足す。
- **通る回数**: 通過も数える。撮る人にとっては通過も撮る機会だから。「16 回（停車 14・通過 2）」のように内訳を出す。通過の済み・残りは、その列車の前後の停車駅の時刻で決める。
- **いまの位置**: いま走っている列車が入っている運用の id で `current-position` を呼ぶ。「推定」の区間の列車は、走っているとは見なさない。
- **編成が見つからないとき**: 選んだ日に有効な編成がその番号に無ければ、上の欄はそのまま出し、「8713 はこの日に有効な編成にありません」と出す。エラー画面にはしない。
- **socket**: リアルタイム運用情報と同じ合図を受けたら、その日の目撃だけを取り直す。ダイヤの列車と乗り移りは取り直さない。今日を出しているときだけ受ける。
- **過去の日付の取り方**: 過去の運用情報と同じく、`from/:start/to/:end` に `includeCarriedOver=true` を付けて、その日の 4 時から翌日の 4 時までを取る。ダイヤはその日付で引く（ダイヤ改正をまたいでも、その日のダイヤになる）。編成番号も、その日に有効な編成を選ぶ。
- **どこまでさかのぼれるか**: ダイヤ（`calendars`）のある日までにする。それより前を選んだら「この日のダイヤはありません」と出す。

## 比べた案

- 運用行路図を編成ごとに出し直す案。行路図は 1 日の折り返しの流れを見渡すには向くが、ある駅の時刻を読み取りにくい。撮る人が知りたいのは何時にどこを通るかなので、時刻の表を本体にし、行路図には運用番号から移れるようにした。
- 名前の候補。「編成行路表」は「運用行路図」と対になるが、行路は運用の言葉で、編成に付けると引っかかる。「編成追跡」はほかのページ名と並べると浮く。URL の `/operation/formation` はユーザーに退けられた。

## 範囲の外

- 2 本の編成がどこで並ぶか・すれ違うか（撮り鉄の「並び」）。あとの段で足す。URL を `/timetable/formation?formation_number=8713&with=8711` のようにパラメータを足せる作りにしておく。
- 撮りたい列車が反対の列車に被られない場所や時刻。あとの段。
- 駅と駅の間の撮影地で何時ごろ通るか（前後の駅の時刻から割り振る）。今回は駅の時刻だけ。
- 明後日より先の見込み。
