# リアルタイム運用情報の帳票化（縦の密度を上げる）設計

-   日付: 2026-10-06
-   対象: `operation/real-time`（2026-08-22 ロック済み・App / index 系の参照実装）
-   ブランチ: `feature/real-time-density`

## 目的

リアルタイム運用情報が縦に間延びしているという利用者の声に応える。

-   桜子さん「最低限情報に絞っても縦に間延びしたなぁって印象」「正直帳票形式みたいな前の圧縮してた方が見やすかったり」「編成と運用の別タブ化はいいね」
-   SO Ltd さん「こっちは前の方が見やすかったかなと思いました」

**情報は削らない**（デザイン改修の絶対原則）。カードの中身はそのままに、外側の作りだけを変えて縦の密度を上げる。

## 実測（改修前と今）

本番 DB の運用 36 件で測った。

|              | 改修前（e954ef34）                        | 今                                                                 |
| ------------ | ----------------------------------------- | ------------------------------------------------------------------ |
| 形           | 表。1 運用 = 1 行で全部の項目が横に並ぶ   | カード。上段に運用・編成・目撃/更新、下段に履歴・現在位置          |
| スマホ 390px | 1 行 48px（入りきらない列は横スクロール） | カード 76〜100px＋間 12px（1 運用あたり約 96px）                   |
| PC 1440px    | 1 行 48px の表                            | 幅 302px のカード 2 列 × 運用順/編成順の 2 組。100〜118px＋間 12px |

## 決定

### 横スクロールは許さない（ユーザー判断）

改修前の表に戻す案は採らない。スマホでも PC でも、画面の横幅に収める。

### スマホ: C「帳票」（ユーザー判断）

実データのカード 8 件を複製して比べた（390px）。

| 案                                     | 8 運用の高さ | 今との比                     |
| -------------------------------------- | ------------ | ---------------------------- |
| A 今のまま                             | 764px        | —                            |
| B カードを詰める（余白 8・間 4）       | 628px        | −18%                         |
| **C 帳票（1 枚の白地を罫線で区切る）** | **607px**    | **−21%**                     |
| D 帳票＋目撃/更新を右に縦通し          | 611px        | 現在位置が折り返して縮まない |
| E 帳票＋履歴を 1 段目の編成の後ろへ    | 535px        | −30%                         |

E は不採用。履歴が多数ある運用で 1 段目が履歴に押し流される（ユーザー指摘）。

### PC: P1「帳票・2 列」（ユーザー判断）

1440px で 12 件を比べた（今は約 672px）。

| 案                     | 12 運用の高さ | 今との比                               |
| ---------------------- | ------------- | -------------------------------------- |
| **P1 帳票・2 列**      | **539px**     | **−20%**                               |
| P2 帳票・1 列で横 1 行 | 631px         | −6%（現在位置の欄が狭く 2 段に割れる） |

## 設計

### 1. 掟の改訂（docs/design.md を先に直す）

-   **面の掟**の「カードに影を付けない。罫線も引かない」に例外を足す。
    -   例外の内容は「**同じ形の小さな記録が多数並ぶリストは、カードを並べず、1 枚の白地を罫線で区切る（帳票）**」。
    -   罫線を引くのは白地の中の行の境だけ。カード同士の境に罫線を引かない掟はそのまま。
    -   経緯として、利用者の声と上の実測（スマホ −21%・PC −20%）を書く。
    -   2026-08-22 に「186 枚並ぶ画面では 1px の枠が視覚的な雑音」として小カードの枠を外した記述との関係も書く。あれは「カードごとの枠」が雑音だったのであって、今回はカードの縁の余白と間 12px を消して行を詰めるのが目的。
-   **`operation/real-time` のロック節**
    -   実測値の表の「カード 角丸 8px・影なし・枠なし」を、帳票の記述に書き換える。
    -   改訂履歴に 2026-10-06 の 1 行を足す。
-   **ドメインの表示規則「リアルタイム運用情報のカード」**
    -   中身の規則（2 行構成・主キー・72px・2.5rem・縦中央そろえ・位置の折り返し）は変えない。
    -   外側が帳票の 1 行になったことを 1 文足す。

### 2. 見た目

| 項目                  | 値                                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 白地                  | 1 枚、`tw-bg-white` + `tw-rounded-card`。中に sticky を持たないので角は overflow で丸めてよい                               |
| 罫線                  | 1px・トークン `rule`（`tw-border-rule` と同じ色）                                                                           |
| 行（1 運用 / 1 編成） | 角丸なし・余白は上下 8px・左右 12px・行の中の段の間は 2px（今は余白 12px・段の間 4px）                                      |
| xl 未満（〜1279px）   | 1 列。行の間に横の罫線（当初は lg 未満。1024〜1110px で編成順カードの時刻が切れたため xl に変更・ユーザー判断 2026-10-07）  |
| xl 以上（1280px〜）   | 2 列。横の罫線に加えて列の間に縦の罫線。同じ段の 2 件は高さをそろえ（行は `height: 100%`）、罫線を一直線にする              |
| 奇数件                | 最後の空いたマスは白のまま（灰色の塊を出さない）                                                                            |
| 対象                  | 運用順（`operation-real-time-operation-table` / `-operation-card`）と編成順（`-formation-table` / `-formation-card`）の両方 |

上の値は Tailwind の `tw-` クラスで書く（任意値は接頭辞なし・`tw-border-solid` を併記）。罫線の実装方法（各行の border か grid の 1px の隙間か）は実装計画で決める。ただし奇数件と絞り込み後の件数の変化で罫線が欠けたり二重になったりしないこと。

### 3. 変えないもの

-   タブ（スマホ）・PC の左右 2 組と見出し・凡例の帯・操作帯
-   カードの中の情報・並び・鮮度の色・取得中の表示・空の状態（`app-empty-state`）
-   ストア・サービス・取得の流れ

### 4. 確かめること（完了の条件）

-   **高さ**：実データで測る。スマホ 390px で 1 運用あたり約 76px 以下、PC 1440px で 12 運用（6 段）が約 540px 以下。
-   **横スクロール**：1440 / 768 / 375 / 320px のどれでも出ない。白地の `overflow-hidden` は中のはみ出しを隠すので、カードごとの `scrollWidth <= clientWidth` も 1440 / 1280 / 1279 / 1100 / 1024 / 768 / 375 / 320px で確かめる。
-   **縦中央そろえ**：上段 3 要素の中心の差 0px のまま（運用順・編成順とも）。
-   **罫線**：PC で奇数件のとき最後のマスが白、絞り込みで件数を変えても罫線が欠けない・二重にならない。
-   **既存の spec**：real-time 配下の jest が通る（`npx jest --testPathPattern=operation-real-time`）。
-   **目視**：390px・1440px のスクリーンショットで、改修前の版・今の版と並べて確かめる。
