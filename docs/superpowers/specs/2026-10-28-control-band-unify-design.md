# 操作帯の畳み方・貼り付き・保存をそろえる

- **日時**: 2026-10-28
- **ブランチ**: refactor/control-band-unify
- **関連**: `src/app/shared/control-band/control-band.component.ts`、docs/design.md「操作帯は貼り付き、どこからでも開ける」、ADR-0014（SSR の描き分け・`afterFirstRender`）

## なぜ

操作帯（`app-control-band`）の扱いがページで 2 通りある（ユーザー指示 2026-10-28「各ページのヘッダー下の白帯のたたみ状態の取り扱い統一したい」）。

- scroll 型（6 ページ）: スクロールすると操作部が隠れ、要約の行だけが貼り付く。畳んだ状態は保存しない。
- manual 型（列車ダイヤグラム・全線時刻表）: ボタンでだけ畳む。畳んだ状態は保存する。

高さ固定（`main` が `calc(100dvh-…)`）はやめない。外すと、横スクロールの箱の中の貼り付く見出しが壊れ、横スクロールバーがページの下端に行き、触ってスクロールするときにページと箱で取り合いになるため（2026-10-28 に説明し、ユーザーは「全部」そろえる方を選んだ）。

## 決めたこと（ユーザー判断 2026-10-28）

1. **畳み方は scroll 型に寄せる。**
2. **畳んだ状態はページごとに保存する。**
3. 高さ固定のページで、箱のスクロールで操作部が隠れた後に「開く」を押すと、**重ねて開く**（scroll 型と同じ）。箱の高さは変わらない。
4. 高さ固定のページで、スクロールで隠れた操作部は、**「開く」でだけ**出す。箱を一番上に戻しても、自動では出さない。

## 振る舞い

### 全ページ共通

- 帯は上から、操作部・要約の行（40px）の順。「畳む」「開く」のボタン、幕、Esc・Tab で閉じる動きは今のまま。
- 「畳む」で畳んだ状態（`collapsed`）を、各ページのストアの `withSettingsStorage` の `controlCollapsed` に保存する。キーはページごとに別。
  - スクロールで隠れた状態は保存しない。保存するのは、ボタンで畳んだ状態だけ。
- 保存した状態を戻すのは、最初の描画の後（`afterFirstRender`。ADR-0014）。SSR では開いた形で描く。今の 2 ページと同じ。

### ページがスクロールするページ（今の scroll 型）

- 今と同じ。要約の行が貼り付き、操作部はヘッダーの下に潜る。
- 違いは、`collapsed` をページのストアとつなぐことだけ。今は部品の中の model で、ページを離れると消える。

### 高さ固定のページ（列車ダイヤグラム・全線時刻表）

- ページ全体はスクロールしない。図・表の箱（以下「箱」）が縦横にスクロールする。
- **利用者が箱をスクロールしたら、操作部をその場で隠して要約の行だけにする。** 隠した分、箱が伸びる（grid の 0fr/1fr で 200ms で動く。今の畳む動きと同じ）。
  - 「利用者がスクロールした」とみなすのは、箱の中で起きた `wheel`・`touchmove`・スクロールのキー（PageUp・PageDown・Home・End・Space・↑↓）だけ。`scroll` イベントでは数えない。
  - プログラムで動かすスクロール（ダイヤグラムの「今」・時刻へ移る、表の向き替え）では隠れない。
  - 2 本指のピンチで拡大縮小しても隠れる（触って動かしたので）。
- スクロールで隠れたら、ボタンは「開く」。押すと、操作部を要約の行の下に**重ねて**開く（幕つき）。閉じると要約の行に戻る。
- スクロールで隠れた操作部は、ページを開き直すまで「開く」でしか出ない。
- 操作部が出ている間の「畳む」は、今の manual と同じ。その場で畳んで保存する。
- ボタンで畳んでいる間の「開く」は、その場で広げる。高さ固定のページは、いつも「一番上にいる」のと同じなので、scroll 型が一番上で広げるのと同じ動きにする。

## 作りの方針

- 部品の型は `collapse: 'page' | 'box'` に改める（`'scroll'`・`'manual'` は消す）。既定は `'page'`。
  - `'page'` は今の scroll 型そのまま。
  - `'box'` は高さ固定のページ用。sticky にしない。`--control-band-offset` を入れない（ページがスクロールしないので、貼り付く物の位置を下げる必要がない）。
- 箱には属性 `data-control-band-scroll` を付ける。部品は `document` で `wheel`・`touchmove`（passive）・`keydown` を聞き、`target.closest('[data-control-band-scroll]')` に当たったときだけ数える。箱の要素を入力で渡さない（全線は箱が子の部品の奥にあるため）。
- `'box'` でスクロールで隠れた状態は、部品の中の signal（保存しない）。
- 重ねて開くのは、今の scroll 型の「畳んだ後に開く」と同じ置き方（要約の行の下に `absolute` で落とす）を使う。

## やらないこと

- 高さ固定をやめること。
- zoneless・他の帯の見た目を変えること。
- 保存の形式（`withSettingsStorage`）を変えること。

## 確かめ方

- 部品の spec（`control-band.component.spec.ts`）に `'box'` の振る舞いを足す: 箱の wheel・touchmove・キーで隠れる／箱の外では隠れない／scroll イベントだけでは隠れない／隠れた後の「開く」は重ねる・閉じると隠れたまま／ボタンで畳む・広げるはその場。
- 8 ページで、畳んでから再読み込みすると畳んだまま開くこと。
- 実データの画面で、412px と 1440px の両方を見る: ダイヤグラムと全線で、箱をスクロールしたら帯が要約の行になり箱が伸びる・「今」では隠れない・重ねて開いた選択欄が選べる。scroll 型のページは前と同じ。

## 追記: 要約の行を上に・初めは畳んだ形（ユーザー指示 2026-10-28）

「要約行を全ての画面で上に持ってくるべきだな。後初期状態を畳んだ状態に」

### 振る舞い

- 帯は上から **要約の行（40px）・操作部** の順にする。全ページ（page・box とも）。
- **初めは畳んだ形**（要約の行だけ）。`controlCollapsed` の初期値・`afterFirstRender` の SSR の値・部品の `collapsed` の初期値を true にする。前に「開く」「畳む」を押して保存してある人は、その値を使う。
- page:
  - 要約の行がヘッダーのすぐ下に貼り付く（`top` = ヘッダーの高さ）。操作部はページの流れの中に置き、スクロールすると要約の行の裏へ潜る。
  - 一番上での「畳む」「開く」はその場で縮める・広げる（今と同じ）。
  - 操作部が要約の行の裏に隠れている間、または畳んだ後にスクロールした後の「開く」は、操作部を要約の行のすぐ下に重ねて出す（幕つき）。ページの形は変えない。
- box: 要約の行が上、操作部が下。箱のスクロールで操作部を隠し、「開く」で要約の行のすぐ下に重ねる。それ以外はこれまでどおり。
- 罫線: 帯の下端にだけ 1 本引く。操作部が見えている間は操作部の下に、隠れている（畳んだ・裏に潜った・スクロールで隠れた）間は要約の行の下に引く。重ねて開いた操作部は自分の下に引く。

### 作りの方針（私の判断）

- page では要約の行を `position: sticky` にする。sticky は親の箱の中でしか貼り付かないので、部品の host と帯の外枠は `display: contents` にし、白地・左右と上の負のマージンは要約の行と操作部にそれぞれ付ける（包む部品はすでに `tw-contents`）。
- 重ねて出す操作部は `position: fixed` にし、開いた瞬間の要約の行の位置（`getBoundingClientRect`）から `top`・`left`・`width` を決める。page では要約の行が止まっているので、開いている間は位置が変わらない。サイドナビがある幅でも、要約の行と同じ幅に重なる。
- 操作部が要約の行の裏に隠れたかは、今と同じく IntersectionObserver で見る。上の余白は「ヘッダー＋要約の行 40px＋1px」にする。
- `hostTop`（負の `top`）と、帯が上から滑り降りる `top` の動きは使わなくなる。重ねたときの動きは、操作部の高さの 0fr→1fr だけにする。

## 追記 2: スクロールで自動で閉じない（ユーザー指示 2026-10-28）

「スクロールしたときに自動で閉じる機能はオミットしよう。ボタン操作だけ。」

- box の「箱のスクロールで操作部を隠す」はやめる（`data-control-band-scroll` も外す）。box はボタンでだけ、その場で畳む・広げる。上の「決めたこと」3・4 と box の振る舞いは、この追記で取り消す。
- page で重ねて開いた操作部も、wheel・touchmove・スクロールのキーでは閉じない。閉じるのはボタン・幕を押す・Esc・Tab で帯の外へ出たとき。
- page で操作部がページと一緒に流れて要約の行の裏へ潜るのは、閉じるのではなく普通のスクロールなので残す。

## 追記 3: 操作部はいつも重ねて出す・開閉は保存しない（ユーザー指示 2026-10-28）

「操作部自体もオーバーレイするかたちにするんだよ?」・保存は「保存をやめる」を選んだ。

- ページの流れの中に置くのは要約の行（40px）だけ。page では要約の行がヘッダーの下に貼り付き、box では貼り付かない。
- 「開く」はどの位置でも、操作部を要約の行のすぐ下に重ねて出す（幕つき・高さの上限は「画面 − ヘッダー − 40px」・0fr→1fr で 0.2 秒）。帯より下の中身は動かない。その場で広げる・畳む動きは無くなる。
- 閉じるのは「畳む」・幕を押す・Esc・Tab で帯の外へ出たとき。
- **開閉は保存しない**。どのページも毎回閉じた形で始まる。上の「決めたこと」2 と追記の「初めは畳んだ形」の保存の部分は取り消す。8 ページのストアから `controlCollapsed` を外し、他に保存するものが無いストアは `withSettingsStorage` と `pageResolver(Store)` も外す。

## 追記 4: 運用行路図も高さ固定に（ユーザー指示 2026-10-28）

「そして、運用行路図ページも固定縦幅に」

- 運用行路図の `main` を全線時刻表と同じ作りにする: `tw-box-border tw-flex tw-h-[calc(100dvh-48px)] tw-flex-col tw-gap-4` ＋ gutter（左右と上は他ページと同じ、下は 16px）＋ `md:tw-h-[calc(100dvh-64px)]`。ページ全体はスクロールしない。
- 帯は `box`（貼り付かない）。
- 図のカード（`app-operation-route-diagram-drawing` の article）が残りの高さを全部取り（`tw-flex-1 tw-min-h-0`）、縦横のスクロールはカードの中の `#scroller` だけが受ける。`#scroller` の `max-h-[calc(100dvh…)]` は外し、カードの残り（ダイヤの帯の下）を全部使う。駅名の貼り付きはそのまま。
- 取る前の骨組みも同じ箱に収める（`calc(100dvh…)` の高さでなく残りの高さ）。空状態（運用番号が未設定）はカードの場所の中央に出す。
