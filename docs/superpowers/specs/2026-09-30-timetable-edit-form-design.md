-   ブランチ: `feature/redesign-2026-07`
-   対象: `src/app/pages/timetable/timetable-edit-form/**`、`docs/design.md`（Material 優先の掟の例外・ロック節）

    スクリーンショット `.context/sample-grid-1440.png` / `.context/sample-grid-390.png`

## 目的

軽量化と UI/UX の 2 つの観点で見直す（ユーザー指示 2026-09-30）。
用途は「既存列車の手直し」と「紙の時刻表からの新規入力」が同じ重さ、端末は PC とスマホの両方（ユーザー回答）。
骨格は本番（https://v3.sotetsu-lab.com の `timetable/update`）を正にする: **列車 = 列（横に並ぶ）× 駅 = 行**、各駅で停車種別と着・発を持つ。

## 現状の問題（実測。ローカル・平日ダイヤ上り・3030 列車・PC 1440px / スマホ 390px）

軽量化

1. デスクトップの表とスマホの縦並びを**両方とも描き**、CSS で片方を隠している。1 列車で DOM 3,046 要素・`mat-form-field` 92 個・ラジオ 84 個
2. 1 駅のセルが 65 要素（`mat-form-field` 1 個 21 要素・ラジオ 3 つ 34 要素）。列車を足すほど線形に増える（本番は全路線の駅を出すので 16,263 要素）
3. 駅・路線・運用・種別・ダイヤの取得 5 本を 1 本ずつ順番に待つ（互いに依存しない）
4. 停車種別ごとの有効・無効を、駅の数だけ `valueChanges` を購読して切り替える

UI/UX

1. **スマホで着時刻を入力できない。** 着の欄は停／通の切替ボタンで、入力欄は発だけ
2. スマホの切替は停 ⇄ 通の往復だけで、「経由なし」に戻せない
3. デスクトップは 1 駅 約 142px（ラジオ 3 つ＋着・発の縦積み）。28 駅で画面 4 枚ぶん、列は細く左寄せ
4. 駅名は `scale` で横に潰す。見出しは平日／土休日の色の帯で、ロック済みページの掟（面・余白・操作部品）と合わない
5. 始発駅の着・終着駅の発は入力できるのに、保存時に黙って捨てる
6. 「列車個別保存モード」の説明が 4 行の長文

## 決定事項（ユーザー判断）

| 項目               | 決定                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 骨格               | 本番が正（列車＝列 × 駅＝行）                                                                                            |
| 時刻の入力         | 案 C（表計算風の自前の格子）と案 A（Material）を実物で比べ、**時刻の格子だけ C、上の行は Material** の折衷（見本で確認） |
| 停車種別の入力     | 3 段の切替（停／レ／‖）。PC・スマホ共通                                                                                  |
| 始発の着・終着の発 | 灰色にして打てなくする（最初と最後の停車駅からその場で決める）                                                           |
| Material 優先の掟  | 時刻の格子を例外として design.md に明記する（理由: 打ち込み速度と 1 セル 65 要素の重さ）                                 |

## 項目ごとの決まり

### 格子（新規 `components/timetable-edit-form-grid/`）

-   1 列車は `停レ‖ ｜ 着 ｜ 発` の 3 欄。PC は 1 列車 164px（停レ‖ 40px・着 64px・発 64px 前後）、1 行 28px。スマホは幅いっぱい・1 行 40px・停レ‖ 44px
-   セルは素の `<button>`（停車種別）と `<input>`（時刻）。`mat-form-field` は使わない
-   駅名の列は左に sticky、「駅｜列番｜着｜発」の 1 行は上に sticky。列車の境目は太い罫線、経由なしの駅の着・発は灰色の地
-   駅名は潰さない（`scale` をやめる）。長い駅名は列を広げる（最長「羽沢横浜国大」が 1 行に収まる幅）
-   数字は `tabular-nums`

### 時刻の打ち方

-   数字だけで打つ。3 桁は先頭に 0 を足し（`930` → `09:30`）、4 桁で `HH:mm` にする。フォーカス中は数字 4 桁、外れると `HH:mm` で見せる
-   `inputmode="numeric"`（スマホは数字キーボード）
-   24 時以降の扱い（保存時に `hour < 4` なら days = 2）は今のまま
-   経由なし（‖）の駅の欄は灰色の空表示のまま打てて、打つと停にする
-   始発の着・終着の発はその駅の行にフォーカスがある間だけ打てる
-   通過（レ）の駅にも時刻を入れてよい（今のデータにある）

### 停車種別

-   停 → レ → ‖ → 停 の循環。クリックかスペースで進める
-   ‖ の駅は着・発を無効にする（今の `NOT_GOING_THROUGH` と同じ意味）。無効化は停車種別から描画時に決め、駅ごとの `valueChanges` 購読はやめる

### キー操作

-   Enter・↓ で下の駅、↑ で上の駅、←→ で隣の欄へ。無効な欄は飛ばす
-   Tab はブラウザの既定のまま
-   `role="grid"`、各セルに「列番 駅名 着／発」の `aria-label`

### 始発の着・終着の発

-   各列車で最初と最後の停車駅（‖ 以外）を描画時に求め、始発の着・終着の発を灰色・無効にする
-   保存時の切り捨て処理（`onClickSubmit`）は残す（念のための二重の守り）

### 誤りの見せ方

-   前の駅より早い時刻はセルを赤い地・赤字にする。04:00 起点で、前の「時刻のある駅」の発（なければ着）と、この駅の着（なければ発）を比べる。
    今の `stopTimesShouldBeLaterThanPrevStopTimes` は時刻の無い通過駅を挟むと比べなかったので、またいで比べるよう強める。
    格子の赤と保存の可否が食い違わないよう、検証器も同じ関数（`findTimeOrderErrors`）を使う
-   駅が 1 つだけ停車のときは、始発の着・終着の発を無効にしない（打った直後に欄が無効になるのを防ぐ）
-   格子の下に「列番: 駅名の着／発（時刻）が前の駅（時刻）より早い」を並べる。停車駅が 2 つ未満のときは「列番: 停車駅が 2 つ以上必要」
-   誤りがある間は保存を押せない（今と同じ `form.invalid`）

### 上の行（Material）

-   ＋／−（`mat-icon-button`）、列車番号（`matInput`）、運用番号・種別（`mat-select`。種別は系統付きの正式名を文字色で出す、塗りチップにしない＝2026-08-22 の指示）、入庫・出庫（`mat-checkbox`）
-   ラベルは列の左の見出し（列車番号・運用番号・種別・入出庫）に出し、各欄の `mat-label` は付けない
-   スマホの「行先」（最後の停車駅から導く読み取り専用の表示）は残す

### ページの上の部分

-   見出しは平日／土休日の色の帯をやめ、掟の見出し（面の掟・余白の掟）にする。改正日・ダイヤ名・上り／下りは全部残す
-   初期値の取り込み（既存列車からコピー・一括オフセット・コピー元の説明）は add / copy に残す
-   路線で絞り込み（畳むパネル）は残す。既定は自社の路線（`ownAgencyRouteIds`）
-   列車個別保存モードは `mat-slide-toggle` と 1 行の説明にし、詳しい説明は補足（ⓘ のツールチップか畳む）に移す
-   操作: PC はカードの下に「クリア・下書き保存・保存する」、スマホは下に sticky（今のまま）。保存するのラベルはモード別（登録／更新）

### データと保存（変えない）

-   Reactive Forms の形（`ITimetableEditForm` / `FormArray`）、検証、保存の DTO 変換、下書きの自動保存と復元、コピー元の選択、`lastSubmittedAt` による初期化は変えない
-   格子は今のフォームの control（`stopType` / `arrivalTime` / `departureTime`）に結ぶ。値は今と同じ `HH:mm`

### 軽量化

-   画面幅で**片方の配置だけを描く**（600px を境に `@if`。CSS の `hidden` で隠さない）
-   取得 5 本（駅・路線・運用・種別・ダイヤ）は `forkJoin` で同時に投げ、その後に update は対象の列車、add / copy はコピー元候補を取る
-   目標: 3 列車 × 28 駅で、ページの DOM を今の 1 列車ぶん（3,046 要素）より小さくする（見本の格子は 872 要素）

## テスト・検証

-   jest: 変換の純関数、始発・終着の位置、早い時刻の検出、格子のキー操作（Enter・矢印・無効欄の飛ばし）、停車種別の循環、‖ に時刻を打つと停、端の時刻の無効化、保存 DTO が今と同じになること（既存の spec を残して通す）
-   実データの目視（ローカル・本番 DB）: update（3030）・add・copy を PC 1440px とスマホ 390px で。見本のスクリーンショットと比べる
-   DOM 要素数と取得の待ち時間を今と比べて記録する
-   保存は本番 DB に書くので、実際の保存の確認はユーザーに頼む（下書き保存と検証までは自分で確かめる）
