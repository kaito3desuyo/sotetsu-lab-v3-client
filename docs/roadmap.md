## 全体の順番

2026-11-10 に、GA と DB の実測（下の「見直しの根拠」）で順番を見直した。本線は次の順に進める。

1. 守り: M19 障害の見張り（エラーの記録の直しを含む）、M7 の「祝日データの最終日が近い」と気づく仕組み、M0 後始末。
2. 投稿の失敗を減らす: M30 投稿のしやすさ。
3. 新しく来た人の定着: M25 使い方と用語（初回の案内を含む）。
4. 編成を追う機能: M12 編成の逆引き → M14 編成ページ。M15 は段を分け、お気に入り → 珍しい運用の知らせ → Web Push の順に出す。
5. M3 臨時列車。先に `calendars.parent_calendar_id` の扱いを決め、本番へ大量に書く前に M24 バックアップから戻す練習を済ませる。
6. M31 共有と X からの流入は、M30 の後に共有ボタンと計測だけを小さく出し、2 週間の数字を見てから画像（M14 と同時）に進む。

本線から外したもの: M4 API の外部公開と M27 登録者限定の MCP サーバー（投稿者が 20 人前後の今は外部の需要が見えない。やるなら余力で）。後ろに下げたもの: M16・M17 ライブラリと M5 段2（今のライブラリは 28 日で 102 PV）、M28 地図（駅の座標が空で、M3・M12 に頼る）、M22 年ごとのまとめ（M14 の後・来年）。M21 運行情報との連携は、機械で取れる口があるかを調べるだけにし、無ければ閉じる。M20 ダイヤ改正の入力支援は、次の改正日が見えたら差し込む。M10・M11 はいつでも差し込める。性能は M12 の前後に差し込み、費用削減も並行で進めるが、手をつける前に計測する。M 番号の外に「ST線開業への対応」の issue（api #83、client #92〜#94）が残っている。他のリポジトリの分は、それぞれの `docs/roadmap.md` にある。

## 見直しの根拠（2026-11-10）

GA は 2026-10-13〜11-09 の 28 日分、DB は本番の実測。

- 利用は横ばい。週の利用者は 12 週つづけて 430〜560 人。再訪者 601 人がセッションの 86% を占め（1 人 11 回）、新規 852 人はほぼ 1 回で終わる。
- 流入は直接 50%、検索 48%、X は 0.5%（39 セッション。うち 30 は登録制の告知で `/register` に着いた分）。
- 見られているのはリアルタイム運用（10,944 PV・滞在の半分超）、トップ、運用行路図、列車位置情報の順。ライブラリは 102 PV。スマホが 75% で、山は 6〜8 時と 17〜19 時。
- 投稿の 14% が失敗している（送信 3,820・失敗 550）。理由は入力の検証で、未来の時刻 226、運用番号が無い 118、始発の 30 分前より前 103、編成が無い 68。
- 投稿者が偏っている。登録制（2026-11-06 21:00）の後、上位 2 人で投稿の 70%、上位 5 人で 92%。1 日の投稿数（95〜145 件）と投稿者数（7〜14 人）は登録制の前後で変わっていない。
- 読み込みの失敗 330 件のうち 253 件は、記録が `[object Object]` で原因が読めない。デプロイ後に古い chunk を読みにいく失敗も 35 人に出ている。
- Search Console の検索語は引けておらず、検索からの伸びしろは確かめていない。
