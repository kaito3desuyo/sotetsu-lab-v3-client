# ADR-0027: ダイヤグラムの図の組み立てを純関数に出し、方向ごとの分割はしない

- **日時**: 2026-11-16
- **Agent**: claude-sonnet-5-5
- **ステータス**: 採用済み
- **ブランチ**: refactor/train-diagram-split
- **関連**: ADR-0004（標準ページ構成）、`.context/review-2026-11-12/fable-code.md` の 4-1、`fable-performance.md` の P8

---

## 決定

- `TrainDiagramComponent` の図の組み立て（computed の鎖 約 45 本）を、純関数 4 段に出した。component は 4 段を `computed` で受けるだけにした。
  - `buildDiagramBase`：全列車・つながりの先頭と末尾・標準の運転時間。方向にも縮尺にも依らない。
  - `buildDiagramPrelude`：方向を絞ったあとのつながり・観測・最小二乗の軸。縦の縮尺には依らない。
  - `buildDiagramLayout`：縦の縮尺の決定・線・折り返し・駅の行。縦の手動縮尺で作り直すのはここだけ。
  - `buildSelectedTripInfo`：選んだ列車の情報。選び直しても前の 3 段は動かない。
  - `buildDiagramModel` は 4 段の合成で、spec 用。本番の component は呼ばない。
- 方向ごとに 2 回呼んで結果を合わせる形（P8）は採らない。合わせた結果が違う。Worker への移し替えもしない。
- 長いタスクは減っていない。この分割は保ちやすさのためで、速度のためではない。

## 背景

- `train-diagram.component.ts` が 1,460 行あり、図の組み立て・URL の読み書き・取得が 1 つに混ざっていた。
- 線の組み立ての長いタスクは、CPU 4 倍で初回 641ms・SPA 移動 731ms（P8）。方向ごとに分けて後回しにできれば、最長のタスクを縮められると見ていた。

## 測ったこと

手元の dev サーバー（CPU 4 倍、`Emulation.setCPUThrottlingRate`）で、割る前（ポート 4200）と割った後（ポート 4201）を比べた。

- 取り方：`PerformanceObserver` の `longtask`。Performance の記録（trace）は使っていない。タスクの中身（どの関数か）は見えない。図の描画の直後に出る最後の長いタスクを、線の組み立てを含むものとして読んだ。
- 初回：同じ URL（`time` を固定）を開き直し、開始から 6 秒の長いタスクを取った。
- SPA 移動：トップを開いて 5 秒待ち、サイドバーのリンクを押してから 5 秒の長いタスクを取った。
- 各 3 回。単位は ms。

| 場面 | 割る前（4200） | 割った後（4201） |
| --- | --- | --- |
| 初回の最後の長いタスク | 502・496・448 | 516・342（前に 120 の別タスク）・474 |
| SPA 移動の最後の長いタスク | 422・443・463 | 370・373・373 |

- 初回は差が出ない。割った後の 3 回目は 2 つに分かれたが、合計は同じ。
- SPA 移動は割った後が 60〜90ms 短い。再計算の範囲を割る前にそろえた（Task 2）ので、遅くなってはいない。短くなった理由は調べていない。dev ビルド 1 回分で、ノイズの範囲かもしれない。
- どちらも dev ビルドで、本番ビルドの数字ではない。P8 の 641ms・731ms は別の環境の数字で、この表とは並べられない。

同じ見た目かどうか：

- `/train-diagram`（`time=1931` 固定）で、`main` の `innerText`（632 文字、ハッシュ一致）、図の線（`polyline`・`line`）の 503 本、`svg path` の 24 本が、割る前と割った後で同じ。
- 図の `innerHTML` から Angular の付ける属性（`_ngcontent-*`・`ng-reflect-*` など）を除くと、170,574 文字でハッシュが一致した。
- 出た警告は NG05001・NG0505 の 2 つで、割る前（4200）にも同じものが出る。dev サーバーは SSR を通さないための警告で、今回の変更とは関係ない。ページの例外は出ていない。
- SPA 移動は「今」から `time` が決まるため、2 つのサーバーの分がずれて、線の本数が 494 と 492 と違った。`time` が 1934 と 1935 で、同じ時刻の入力ではない。見た目の一致は上の固定 URL で確かめた。
- SSR した HTML と hydration 後の一致は、dev サーバーでは見られない。本番ビルドで別に確かめる。

## 方向ごとの分割を試した結果

Task 1 の fixture で、`buildDiagramModel` を `directionFilter: 'up'` と `'down'` で 2 回呼んで合わせ、`'both'` で 1 回呼んだ結果と比べた。

- 線：合わせた結果が `both` と違う。
- 折り返しの線：上りだけ 0 本、下りだけ 0 本、`both` で 2 本。折り返しは上りの列車と下りの列車をつなぐので、方向ごとに組むと出てこない。
- 駅の行：上りだけ・下りだけのどちらも `both` と違う。高さは同じ 116。

折り返しが方向をまたぐため、方向ごとに組んで合わせることはできない。試しの spec と実装は消した（実装は変えていない）。

## 結果

- component は 1,460 行から 761 行になった。400 行前後には届いていない。残りは URL・取得・effect・template との橋渡し。
- 図の組み立ては純関数になり、`train-diagram.snapshot.spec.ts`（Task 1）と `train-diagram.recompute.spec.ts`（縮尺・選択・方向で再計算する範囲）で固定している。
- 長いタスクを縮めるなら、別の手が要る。候補は、折り返しを含む全体を Worker に移すこと、線の組み立てを時間で刻んで譲ること。今回は、どちらも測っていない。
