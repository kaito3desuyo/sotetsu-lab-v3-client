# ADR-0019: 操作帯の畳み方・保存を全ページでそろえる

- **日時**: 2026-10-28
- **Agent**: claude-opus-5-5
- **ステータス**: 採用済み
- **ブランチ**: refactor/control-band-unify
- **関連**: spec `docs/superpowers/specs/2026-10-28-control-band-unify-design.md`、docs/design.md「操作帯は貼り付き、どこからでも開ける」、ADR-0014（SSR の描き分け）

---

## 背景

- 操作帯（`app-control-band`）の扱いが 2 通りあった。
  - scroll 型（6 ページ）: スクロールで操作部が隠れ、要約の行だけが貼り付く。畳んだ状態は保存しない。
  - manual 型（列車ダイヤグラム・全線時刻表）: ボタンでだけ畳む。畳んだ状態は保存する。
- ユーザーは扱いをそろえたいと言った（2026-10-28）。manual 型の 2 ページは、画面の高さに箱を固定し、図・表をその中でスクロールさせている。

## 決定

- **高さ固定はやめない。** 外すと次のことが起きる。
  - 横スクロールの箱の中の貼り付く見出し（全線の 3 段の見出し・ダイヤグラムの駅名の列）が効かなくなる。
  - 横のスクロールバーが表の下端（ページの下端）まで行く。
  - 触ってスクロールするとき、ページと箱で取り合いになる。
  - ダイヤグラムの「見えている範囲だけ描く」処理を作り直すことになる。
- **畳み方は scroll 型に寄せる**（ユーザー判断）。`collapse` を `'page' | 'box'` に改める。
  - `page` は今の scroll 型のまま。
  - `box` は高さ固定のページ用。箱に `data-control-band-scroll` を付ける。その中で利用者がスクロール（wheel・touchmove・スクロールするキー）したら、操作部を隠して要約の行だけにする。浮いた高さは箱が使う。
  - `scroll` イベントでは数えない。数えると、ダイヤグラムの「今」・時刻へ移るといった、プログラムが動かすスクロールでも隠れてしまう。
  - 箱は入力で渡さず、`document` で聞いたイベントの target を `closest()` で見て判断する。全線の箱は子の部品の奥にあり、入力で渡すと何段も通すことになるため。
- **スクロールで隠れた後の「開く」は重ねて開く**（ユーザー判断）。箱の高さは変えない。閉じると隠れたまま。箱を一番上に戻しても、自動では出さない（ユーザー判断。ダイヤグラムは横が主なので「一番上」の意味が薄く、2 ページで同じ規則にできる）。
- **ボタンで畳んだ状態は、ページごとに保存する**（ユーザー判断）。
  - 各ストアの `controlCollapsed` を `withSettingsStorage` で保存する。保存の無かった 4 ページ（駅別・過去の運用・運用行路図・列車位置情報）は、route を `pageResolver(Store)` にして読み込みを待つ。
  - スクロールで隠れた状態は保存しない。
  - SSR では開いた形で描き、保存した値は最初の描画の後に戻す（`afterFirstRender`）。
- 重ねて開いた帯の中の選択欄を開いても、帯を閉じない。Material 22 の選択肢のパネルは popover に出るので、`.cdk-overlay-container` に加えて `[popover]` へのフォーカス移動も帯の中と同じに扱う。
