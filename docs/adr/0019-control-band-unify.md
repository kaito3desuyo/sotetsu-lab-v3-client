# ADR-0019: 操作帯は要約の行だけを置き、操作部は重ねて開く

- **日時**: 2026-10-28
- **Agent**: claude-opus-5-5
- **ステータス**: 採用済み
- **ブランチ**: refactor/control-band-unify
- **関連**: spec `docs/superpowers/specs/2026-10-28-control-band-unify-design.md`（追記 1〜4 が最終の形）、docs/design.md「操作帯は貼り付き、どこからでも開ける」、ADR-0014（SSR の描き分け）

---

## 背景

- 操作帯（`app-control-band`）の扱いが 2 通りあった。
  - scroll 型（6 ページ）: スクロールで操作部が隠れ、要約の行だけが貼り付く。畳んだ状態は保存しない。
  - manual 型（列車ダイヤグラム・全線時刻表）: ボタンでだけ畳む。畳んだ状態は保存する。
- ユーザーは扱いをそろえたいと言った（2026-10-28）。manual 型の 2 ページは、画面の高さに箱を固定し、図・表をその中でスクロールさせている。
- 初めは scroll 型に寄せ、高さ固定のページでは箱のスクロールで操作部を隠し、ボタンで畳んだ状態を保存する形で作った。そのあとユーザーの指示で、次の決定の形に改めた。

## 決定

- **ページに置くのは要約の行（40px）だけにする。操作部は、どの位置でも要約の行のすぐ下に重ねて開く**（ユーザー指示）。帯より下の中身は動かない。
  - 要約の行は帯の一番上に置く。初めは閉じた形。
  - その場で広げる・畳む動きは無くした。重ねるので、ページの形が変わらない。
- **閉じるのはボタン操作だけにする**（ユーザー指示）。「畳む」・幕を押す・Esc・Tab で帯の外へ出たときに閉じる。スクロールでは閉じない。箱のスクロールで隠す仕組みも外した。
- **開閉は保存しない**（ユーザー判断）。開いた形を保存すると、読み込むたびに中身に操作部がかぶさる。ダイヤグラム・全線にあった `controlCollapsed` の保存も外した。端末に残る古いキー（`TrainDiagramStore`・`TimetableAllLineStore`）は読まれないだけで害は無い。
- **高さ固定はやめない。** 外すと次のことが起きる。
  - 横スクロールの箱の中の貼り付く見出し（全線の 3 段の見出し・ダイヤグラムの駅名の列・運用行路図の駅名）が効かなくなる。
  - 横のスクロールバーが表の下端（ページの下端）まで行く。
  - 触ってスクロールするとき、ページと箱で取り合いになる。
- **運用行路図も高さ固定にする**（ユーザー指示）。全線時刻表と同じく `main` を `100dvh − ヘッダー` にし、図のカードの中がスクロールする。
- `collapse` は `'page' | 'box'`。違いは要約の行が貼り付くかどうかだけ。
  - `page`: 要約の行を `position: sticky` にする。sticky は親の箱の中でしか貼り付かないので、部品の host と帯の外枠は `display: contents` にする。
  - `box`: 高さ固定のページ用。貼り付かない。
- 重ねた操作部は、要約の行の下に `position: absolute`（`top: 100%`）で置く。要約の行が貼り付いている（page）か、ページが動かない（box）ので、位置を測らなくても要約の行についてくる。
- 重ねて開いた帯の中の選択欄を開いても、帯を閉じない。Material 22 の選択肢のパネルは popover に出るので、`.cdk-overlay-container` に加えて `[popover]` へのフォーカス移動も帯の中と同じに扱う。

## 結果

- 手元（本番 DB）で 412px と 1440px の両方を見た。8 ページとも次のとおりだった。
  - 初めは閉じた形で、要約の行がヘッダーのすぐ下にある。
  - 「開く」で重ねても、帯の下の中身の位置は変わらない。
  - 開いたまま wheel でスクロールしても閉じない。Esc で閉じる。
  - ページを下へ送ってから開いても、要約の行はヘッダーのすぐ下にあり、操作部はその下に重なる。
- 運用行路図はページがスクロールせず、図のカードの中を縦に送っても駅名が上に貼り付いたままだった。
- 重ねて開いたダイヤグラムの帯で、ダイヤを選び替えられた。
